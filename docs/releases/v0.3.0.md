# AI Intel Workbench v0.3.0

v0.3.0 makes every scheduled research claim auditable. A digest can no longer mark broad coverage as complete unless the underlying queries, provider results, candidate counts, and domestic-lab checks exist as inspectable evidence artifacts.

## Why this release exists

A scheduled run on 2026-07-22 exposed three workflow failures:

- A small number of broad web searches could be rewritten as eight completed coverage groups and 24 completed domestic-lab checks.
- Gate CLI could return a fluent X summary while `cited_tweets` and `items` were empty.
- X could still display `Loading` immediately after `domcontentloaded`, causing a first-viewport snapshot to report a false empty result before the search timeline appeared.

This release treats those as execution and evidence failures rather than as proof that no current discussion exists.

## Auditable research trace

- Adds `scripts/research_trace.py` with `init`, `record`, `check`, and `finalize` commands.
- Stores each run's provider, query group, exact query, execution time, status, result count, candidate URLs, concrete X post URLs, and evidence-artifact path.
- Requires all eight mandatory query groups and all eight core domestic labs across `model_release`, `product_ops`, and `research` tracks.
- Scopes combined evidence artifacts to the exact query recorded by each run, preventing duplicate candidate accounting.
- Rejects artifacts outside the current run directory.

## Quality version 5

- Requires a finalized same-day `research_trace.json` and trace-backed `run_ids` for every query group.
- Cross-checks query text, candidate counts, Gate/public-index/browser totals, and 24 lab/track pairs against the trace.
- Requires at least three real Gate X queries and at least four fallback queries when Gate returns fewer than four concrete cited posts.
- Requires at least 12 items with minimum representation across labs, KOL viewpoints, papers, open source, and AI-finance.
- Preserves non-X dimensions when X evidence is insufficient instead of emitting an empty digest.

## Safer scheduled X fallback

- Uses Gate only for candidate discovery; summaries without concrete cited posts are rejected.
- Falls back to public web indexes, then to a locally configured read-only X search when indexes return only trending or profile pages.
- Caps scheduled browser work at six first-viewport searches and eight visible posts per query.
- Waits for the search timeline or article content, including a short post-load wait when X still shows `Loading`.
- Does not scroll, visit profiles in bulk, or perform likes, follows, reposts, posts, or messages; it stops on login walls, CAPTCHA, or challenges.
- Keeps X-only operators such as `since:` and `filter:` out of ordinary web-search templates.

## Validation and sample result

- Adds unit coverage for complete traces, out-of-run artifact rejection, and exact-query scoping for combined artifacts.
- The repaired 2026-07-22 run produced 38 trace records: 8/8 query groups, 3 Gate searches, 4 public-index searches, 6 read-only X searches, and 24 domestic-lab track checks.
- Its resulting local digest contains 18 items, with 10 from the previous 72 hours, 15/18 from the previous seven days, 5/5 KOL items backed by concrete X posts, and no repeated URL from the previous seven digests.

## Upgrade notes

- Existing legacy digests remain readable in compatibility mode.
- New production digests should use `quality_version: 5` and a finalized same-day research trace.
- Evidence artifacts under `.daily-intel/`, local browser state, webhooks, tokens, cookies, and automation-specific configuration remain local and are not part of the release.
- Keep real bot webhooks in `config/secrets.env` or environment variables. Scheduled pushes should continue to use `primary_only` and a dry run before delivery.
